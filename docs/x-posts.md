## E. スレッド案（D の続き）
1/ きっかけは第三者評価。「複式簿記家計簿を作ること自体が差別化にならない」とハッキリ言われた。Firefly III / Actual / ezBookkeeping / MoneyBalance / Dualy …もう競合だらけ。

2/ でも棚卸ししたら、武器はもう持ってた。①家族の純資産（NISA/iDeCo/ローン込み）②運営者にも読めないE2E ③一行入力→自動複式。バラバラだったのを1つのコンセプトに束ねた。

3/ 看板を「複式簿記の家計簿」→「家族の純資産OS × ゼロ知識プライバシー × 摩擦ゼロ入力」に。コードはほぼ据え置き、変えたのは“言葉・見た目・SEO”。Claude Design→Claude Codeで全面刷新。

4/ 学び：個人開発で難しいのは「作れるか」じゃなく「どこで戦うか」。差別化は新機能より“既存機能の束ね方”で生まれることがある。
