# 他の家計簿アプリからの移行（汎用化）（2026-09-23）

「複式家計簿」（Android）からの移行ツール（`docs/plan-migrate-fukushiki-2026-09.md`、実装済み・未デプロイ）を、ほかのアプリの書き出しファイルでも使えるようにする。形式は **CSV と JSON だけ**。今の「科目の割り当て」の画面の前に「列の対応付け」の画面を1枚足し、どの列が日付・金額・科目なのかを利用者が指定する。

**複式家計簿は「決まった対応付け」の1つとして残す。** 見出しから自動で判定して列の対応付けを飛ばすので、今の動きは変わらない。

## 決まっていること（2026-09-23）

- 単式の家計簿データ（マネーフォワード・Zaim・自作の Excel 家計簿など、1行＝1取引で借方・貸方の無いもの）も対象にする。
- JSON は「取引の配列を選び、各項目を列として平らに並べる」まで。取引が ID しか持たず、名前が別の配列にある形（ID の引き直し）は対象外。
- 既存の CSV 取込（`components/Journal/CSVModal.jsx`、銀行明細向け）は別のまま。変更しない。マネーフォワードと Zaim は、移行側でも決まった対応付けとして自動判定する（既存の CSV 取込と同じ読み方）。

## 共通のルール

前回の計画書と同じ。

- 本番への干渉（S3 sync / invalidation / sam deploy / change-set execute）は毎回ユーザーの明示許可を取る。今回もフロントのみで、バックエンドには触らない。
- 取込はすべて端末の中で行う。家計データを運営側に送らせない。
- 書き込みは既存の `addAccount` / `addJournal`。`/api/import` は使わない。
- 余分な diff を出さない。

## 入力

### CSV

- 文字コード・区切りは今と同じ（`readCsvFile`、見出し行にタブがあればタブ）。
- 「1行目は見出し」のチェックを置く（既定オン）。外すと列の名前は「列1」「列2」…にする。

### JSON

- ファイル全体を読み、**オブジェクトの配列**を候補として一覧にする（最上位が配列ならそれ、オブジェクトならその中の配列。入れ子もたどる）。利用者が1つ選ぶ。
- 選んだ配列の各要素を1行とし、項目を列にする。入れ子のオブジェクトは `account.name` のようにドットでつないだ列名にする。要素の中の配列は列にしない。
- **配列の中の配列を選んだときは、親の項目も列として引き継ぐ**（`親.date` など）。あわせて「親の番号」の列を足す。複式の JSON に多い `[{ date, memo, lines: [{ account, side, amount }] }]` の形なら、`lines` を選んで「親の番号」を仕訳No に当てれば、1仕訳ずつ正しく束ねられる。
- どの形でも、ここから先は CSV と同じ「列の対応付け」に進む。

## 変換の仕様

### 1. 元データの形（3つから選ぶ）

| 形 | 例 | 1行が表すもの |
|---|---|---|
| **1行＝1明細** | 複式家計簿の仕訳1、会計ソフトの仕訳 | 仕訳の1明細（借方か貸方の一方） |
| **1行に借方と貸方** | 複式家計簿の仕訳3 | 借方と貸方（どちらかが空の続きの行もある） |
| **単式** | マネーフォワード、Zaim、自作の家計簿 | 1つの取引（収入・支出・振替） |

### 2. 列の対応付け

形ごとに、次の項目へ列を割り当てる（プルダウンで列を選ぶ）。

**1行＝1明細**
- 必須：日付・科目・金額・貸借
- 貸借の決め方：「貸借の列」（借方を表す値を選ぶ。例：借／借方／D／debit）か、「金額の符号」（プラス＝借方、マイナス＝貸方）
- 任意：補助科目・摘要・仕訳No・科目コード

**1行に借方と貸方**
- 必須：日付・借方科目・借方金額・貸方科目
- 任意：借方補助科目・貸方補助科目・貸方金額（無ければ借方金額と同じ）・摘要・仕訳No・借方/貸方の科目コード

**単式**
- 必須：日付・金額・カテゴリ（振替の行を除く）
- 口座：口座の列を選ぶか、列が無いファイルなら「すべてこの口座」として1つ選ぶ（例：現金）
- 収支の決め方（4通りから選ぶ）
  - 金額の符号（マイナス＝支出）
  - 収支区分の列（収入を表す値・振替を表す値を選ぶ。それ以外は支出）
  - 入金額の列と出金額の列が別
  - 出金元の列と入金先の列（入金先だけ＝収入、出金元だけ＝支出、両方＝振替。Zaim の形）
- 任意：補助カテゴリ・振替先の口座（値があれば振替）・摘要
- 仕訳への組み替え
  - 支出：借方＝カテゴリ／貸方＝口座
  - 収入：借方＝口座／貸方＝カテゴリ
  - 振替：借方＝入金先の口座／貸方＝出金元の口座

**どの形でも使えるもの**
- 取り込まない行：列と値の組を指定する（例：`計算対象` が `0`、`削除する場合「1」` が `1`）。複数指定できる。件数を数えて画面に出す。
- 金額は絶対値で扱う（符号は上の「貸借」「収支」の決め方にだけ使う）。金額が0か空の行は取り込まず、数える。
- 日付は既存の `normD` で読む（`2025/1/15`・`2025-01-15`・`20250115`・`25/1/15`）。読めない行はエラーにする。

**画面で確かめられるようにする**：対応付けを変えるたびに、先頭の数件を仕訳に変換した結果（日付・借方・貸方・金額）と、エラー・除外の件数をその場で出す。

### 3. 仕訳へのまとめ

- 1行＝1明細：今と同じ（借方と貸方の合計が合うまで束ねる。仕訳No が数字だけなら番号の変わり目でも区切る。日付が変わったらエラー。100明細まで）。JSON の「親の番号」は数字なので区切りに使える。
- 1行に借方と貸方：今の仕訳3と同じ。
- 単式：1行＝1仕訳（束ねない）。

### 4. 科目の割り当て

今の画面をそのまま使う。変えるのは次の点。

- 組の単位：科目コードの列があれば今と同じ（科目コード＋補助科目コード）。無ければ **科目名＋補助科目名**。単式ではカテゴリと口座を別に扱う（同じ名前のカテゴリと口座を1つにまとめない）。
- 新しく作る名前：今と同じ規則（補助科目があれば「科目名（補助科目名）」）。
- 区分の推定
  - 科目コードの列があれば、今と同じく先頭の桁（1〜5）から。
  - 単式では、口座→資産、支出の行のカテゴリ→費用、収入の行のカテゴリ→収益（両方に出るカテゴリは多いほう）。
  - それ以外は空。空の科目がまとめて選べるよう、「区分が空の科目をまとめて設定」を置く（科目コードの無い複式のファイルでは、全部が空になるため）。
- 並び順：科目コードがあれば今と同じ。無ければ明細数の多い順。
- コードの採番・非表示（科目ファイルがあるとき）・自動の割り当て（`resolveAccount`）は今と同じ。

### 5. 重複の除外・書き込み

今と同じ（既存1件につき1件まで重複として外す。摘要は200文字。失敗したらそこで止める）。

## 決まった対応付け（自動判定）

見出しで判定し、当てはまれば列の対応付けを飛ばして科目の割り当てへ進む。「対応付けを見直す」で列の対応付けの画面を開ける。

| 名前 | 判定（見出し） | 中身 |
|---|---|---|
| 複式家計簿 仕訳1 | `貸借` がある | 今の変換そのまま（削除フラグ・外貨の除外、科目コードから区分を推定） |
| 複式家計簿 仕訳3 | `科目コード(借)` がある | 同上 |
| 複式家計簿 科目 | `補助簿` がある | 今と同じく、仕訳ファイルに名前と非表示を補う（このときだけ2ファイル） |
| マネーフォワード | 既存の `detectCsvFormat` が `mf` と判定 | 既存の CSV 取込と同じ読み方（`計算対象`=0 を除外、符号で収支、口座＝`保有金融機関`、カテゴリ＝`大項目`、摘要＝`内容`） |
| Zaim | 既存の `detectCsvFormat` が `zaim` と判定 | 既存の CSV 取込と同じ読み方（出金元・入金先の形、カテゴリ＝`カテゴリ`、摘要＝`品目`→`お店`→`メモ`） |

- 決まった対応付けも、画面から作るものと同じ「対応付けのデータ」で表す（別の読み取り処理を持たない）。そのため、既存の CSV 取込が「A列が空なら B列」と読んでいる所は、対応付けのデータで列を複数持てるようにする（画面からは1列だけ選ぶ）。
- マネーフォワード・Zaim は既存の CSV 取込と同じ読み方なので、既存の読み方の限界もそのまま引き継ぐ（例：マネーフォワードの振替の行も、カテゴリ「振替」の支出・収入として読む）。

## 実装で決めたこと（2026-09-24）

- **Zaim は既存の CSV 取込と同じ読み方にしなかった（計画書と違う）。** Zaim の書き出しに「金額」の列は無く、金額は支出・収入・振替の3列（使わない列は 0）に入る。既存の CSV 取込は「金額」の列を読むため、実際の Zaim では0件になる。同じにすると移行でも0件になるので、実際の列から読む。既存の CSV 取込は変えていない（直すかどうかは別に決める）。
- 日付の後ろに時刻があれば外して読む（Firefly III など）。
- 仕訳No は「数字だけ」でなくても、値があり指数表記に化けていなければ区切りに使う（JSON の「親の番号」や英数字の伝票番号のため）。
- 列を複数指定した金額は、0 でない最初の列を使う（Zaim の3列のため）。
- 画面で足したばかりで列か値が決まっていない「取り込まない行」の条件は使わない。
- JSON の配列の候補は、件数のいちばん多いものを既定にする。
- 移行パターン（6つ）の結果と出典、見送ったアプリは `docs/design-gen/migrate-fukushiki-2026-09.xlsx`（Google スプレッドシートにも同じもの）。

## 画面の作り直し（2026-09-25 にユーザー決定）

画面を触ってもらったところ「マッピングが分かりにくい」「『← 列の対応付け』も分かりにくい」「最初からマッピング画面に行ってほしい」「項目の下に選択肢を置くのではなく、左右でマッピングが分かるように」と指摘を受けた。上の「画面」の節（列の対応付け → 科目の割り当ての2枚）は、次のとおり置き換える。

- **流れは「ファイルを選ぶ → マッピング → 取込」。** ファイルを選ぶとすぐマッピングの画面に進む（「次へ」は無い）。決まった形式（複式家計簿・マネーフォワード ME・Zaim）も飛ばさず、マッピングを入れた状態で出す。
- **マッピングは1枚の画面。** 上が「列のマッピング」、下が「科目のマッピング」で、その画面から取り込む。列を変えると、見本・仕訳の件数・科目の一覧がその場で変わる。科目のマッピングで手で変えたところは、列を変えても残る（科目の組ごとに持つ）。
- **列のマッピングは、左＝元のファイルの列（見本の値つき）、右＝くろふくぼの項目。** 列は全部並べ、使わない列は「使わない」。同じ項目に2つ以上の列を選べる（値のある最初の列を使う。Zaim の支出・収入・振替 → 金額など）。
- **収支・貸借の決め方の選択肢は無くした。** どの項目に列を選んだかで決める（`mapping.js` の `deriveModes`）：入金額・出金額 → 出金元・入金先 → 収支区分 → どれも無ければ金額の符号。貸借の列が無ければ金額の符号。決め方は表の下に文で出す。貸借・収支区分の列の値（「借」→借方など）は、その列の行のすぐ下で割り当てる。
- **戻るボタンは「ファイルを選び直す」だけ。** 「1行目は見出し」・JSON の配列の選択・複式家計簿の科目のファイル（kamoku.csv）は、マッピングの画面の上に置いた。科目のファイルの欄は科目のファイル以外を受け付けない（仕訳のファイルと取り違えないため）。
- 列の表・科目の表は、モーダルの中でさらにスクロールしないよう高さを抑えない（モーダル全体がスクロールする）。
- **取り込めない理由を画面で分かるようにした（同日、ユーザー指摘）。** 「取り込まない行の説明が分からない」「サンプルで次に進めない原因が分かりにくい」への対応：
  - 取り込まない行の条件は文で出す（「通貨名 の列が空でも『日本円』でもない行（日本円以外）」）。上に「当てはまる行は取り込まずに読み飛ばす」と説明を置いた。見出しは「削除の印」「日本円以外」「金額が0」に言い換えた。
  - 読み飛ばした行は、理由ごとに件数と行番号を出す（「金額が0 → 1行（行 1）」）。
  - 貸借が合わないエラーは、区切れた理由（日付・仕訳No・ファイルの終わり）によらず「借方と貸方の金額が合いません（借方 0・貸方 100）」に揃え、その仕訳にまとめた行の中身（行番号・日付・借方か貸方か・科目・金額）を並べる。赤い枠の上に、仕訳のまとめ方と「元のアプリでその行の金額を確かめて」を書いた。
  - 取込ボタンが押せないときは、下端に理由を必ず出し、その場所まで送るボタン（「理由を見る」「列のマッピングへ」「科目のマッピングへ」「チェックの場所へ」）を添える。全件が取込済みで押せないときも理由を出す（以前は何も出ていなかった）。

## 仕訳明細の画面（2026-09-25 にユーザー決定）

「科目のマッピングのエラーは、こちらで直せるようにしたい。科目のマッピングの次に画面を作って、仕訳明細のマッピングを」を受けて追加した。

- **流れは「ファイル → マッピング → 仕訳明細 → 取込」。** 仕訳明細は、エラーの有無によらずいつも通る。取込ボタンは仕訳明細の画面だけにあり、マッピングの画面のボタンは「次へ（仕訳明細）」になった。
- **出す仕訳は全部。** 仕訳にできたものと、明細はあるのに仕訳にできなかったもの（貸借が合わない・日付や貸借が読めない）を、ファイルの順に並べる。並び順は「ファイルの順・日付の順・科目の順」から選べる。科目の順は仕訳をまたいで行を並べ替える（同じ科目の行が続けて見える。「#番号」が同じ行が1つの仕訳）。
- **直せるもの：日付・借方か貸方か・科目・金額、行を足す・消す。** 日付は仕訳ごと。行を足すと、借方と貸方の差額が足りない側に入った状態で出る（科目だけ選べば合う）。科目は「ファイルの科目（科目のマッピングのとおり）」と「くろふくぼの科目」から選べる。
- 取り込めない仕訳は赤くし、直すまで取り込まない。残っていても、ほかの仕訳は取り込める（下端に件数と「直す仕訳へ」）。「直す仕訳へ」は今の並びで次の赤い仕訳へ順に送る。
- 取込済みと同じ仕訳（重複）の判定とチェックは、この画面に移した。
- マッピングの画面では、直せる仕訳は件数だけ出して「次の画面で直せます」と案内する。明細も作れなかった行（科目が空など）は、列の読み方の問題なので、これまでどおりマッピングの画面に赤い枠で出す。
- 科目の組（科目のマッピングの一覧）には、直せる仕訳の科目も含める。
- マッピングの画面に戻って列を変えると、仕訳明細で直した内容は作り直しになる（画面に書いてある）。列を変えずに戻って進んだときは残る。
- 1ページ100行で表示する（数千行を一度に並べると入力欄が重くなるため）。
- 処理は `utils/migrate/review.js`（仕訳の組み立て・取り込めるかの判定・足す行の初めの値・並べ替え）、画面は `components/Settings/JournalReviewStep.jsx`。
