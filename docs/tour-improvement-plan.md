# ツアー離脱対策 実装計画（2026-07-31）

## 背景と目的

はじめてのツアー（firstRun）の通過率が低い。直近14日（母数60人）の実測値：

| 段階 | 到達 | 残存率 |
|---|---|---|
| ①ようこそ | 60 | 100% |
| ②口座を登録 | 29 | 48% |
| ③純資産 | 8 | **13%** |
| ④完了 | 5 | 8% |

明示スキップは①で11人、②で8人。**②→③で21人が脱落しているのに、スキップを押したのは8人だけ**。残り13人は「スキップも押さず消えた」＝口座登録の作業で詰まっているか放置離脱。

目的は②の関門を緩め、③（純資産が見える＝このアプリの価値が伝わる瞬間）への到達率を上げること。

## 根本原因

`Tour.jsx` の②ステップは `awaitAccount: true` のゲート仕様。実際に口座を追加しない限り次に進めない。そしてゲート時のボタン描画がこうなっている（Tour.jsx 392-394行付近）：

```jsx
{gated
  ? (step.prefill && <button ...>✍️ 入力例を自動入力</button>)   // ②は prefill 未定義 → 何も描画されない
  : <button ...>次へ →</button>}
```

**②では `prefill` が未定義のため、右下の主ボタンが一切描画されない。** 画面には控えめな「あとで」しか出ず、前進する手段が視覚的に存在しない状態になっている。これが13人の無言離脱の有力な原因。

さらに `showSample`（📊サンプルで見る）は `step.key === 'welcome'` 限定のため、②では使えない。①を通過した人には逃げ道がない。

## 変更方針（2026-07-31 ユーザー指示により修正）

**口座登録を必須から外し、スキップしても次へ進めるようにする。** 当初は「ゲートを残したまま逃げ道を足す」案だったが、ユーザー判断でゲート自体を撤廃する。

実際に口座を追加した場合は自動で次へ進む挙動（`awaitAccount`）は維持し、追加しなくても「次へ」で③へ進めるようにする。

### 1. ②に「サンプルで見る」の逃げ道を出す（最優先・最小変更）

`showSample` の条件を `welcome` 限定から `account-add` も含めるよう変更する。

```js
// 変更前
const showSample = step.key === 'welcome' && sampleAvailable && journals.length === 0;
// 変更後
const showSample = (step.key === 'welcome' || step.key === 'account-add')
  && sampleAvailable && journals.length === 0;
```

`trySample()` はサンプル投入後 `networth` ステップへジャンプする実装済みなので、②から押せば③に到達できる。**口座登録が面倒な人を③へ運ぶ経路ができる。**

### 2. ②のゲート時にも主ボタンを描画する

`prefill` がないと主ボタンが消える現状を修正。②では「サンプルで見る」を主ボタン（btn-p）に格上げして右下に置く。

### 3. ②の文言を、作業量が軽く見えるよう調整

現在：「使っている銀行口座やカードを選んで保存しましょう。『いまの残高』も入れておくと…」
→ テンプレのワンタップで済むこと、残高は任意で後からでもよいことを明示する。

### 4. ①の文言を調整（スキップ11人への対策）

現在の「30秒で体験しましょう」に対し、実際は口座登録という作業が挟まる。期待と実際のズレを減らす方向で調整する。

## 触らないもの

- ゲート（`awaitAccount`）自体は維持。行動を伴わない完走は価値がないため
- ③④のステップ内容
- 他ツアー（journalDetail / credit / simple 等）
- 計測イベント名（`tour_step_*` / `tour_skip_*`）。変えると過去データと比較できなくなる

## 対象ファイル

- `frontend/src/components/Onboarding/Tour.jsx`（TOURS.firstRun の文言、showSample条件、ゲート時のボタン描画）
- `frontend/src/config/updates.js`（更新情報。ユーザー向け価値が薄いため記載は任意）

## 検証

1. `vite build` が通ること
2. Playwrightで新規ゲスト状態からツアーを起動し、②で主ボタンが描画されることを確認
3. ②の「サンプルで見る」→ ③純資産ステップに到達し、純資産に数字が入っていることを確認
4. 従来経路（テンプレから口座を実際に追加 → ②が自動で次へ進む）が壊れていないことを確認
5. `tour_step_*` イベントが従来通り発火することを確認

## 効果測定

デプロイ後1〜2週間の `tour_step_networth / tour_step_welcome` を現状13%と比較する。母数が週30人程度なので、有意差の判断には2週間程度必要。
