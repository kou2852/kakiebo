# 「複式家計簿」アプリからの移行ツール（2026-09-23）

Android の「複式家計簿」（com.gomao.kakeibo）を使っている利用者から、くろふくぼへのデータ移行を要望された。書き出しファイルの列構成を教えてもらったので、それをもとに取込機能を作る。返信は済んでいる。

**補助科目は、くろふくぼの科目を分けて表す。** くろふくぼに補助科目の仕組みは無いので、「普通預金／銀行 亀支店」「普通預金／ゆうちょ銀行」のような科目＋補助科目の組ごとに、別々の科目として作る（後述）。

## 共通のルール

- 本番への干渉（S3 sync / invalidation / sam deploy / change-set execute）は、**毎回ユーザーの明示許可を取る**。今回はフロントのみの変更で、バックエンドには触らない。
- 取込は**すべて端末の中で行う**。利用者の家計データを運営側に送らせたり、サーバー側で変換したりしない。
- 既存の CSV 取込（`components/Journal/CSVModal.jsx`、銀行明細向け）は変更しない。移行は別のモーダルにする。1行＝2明細の仕訳という前提で作られており、複合仕訳に曲げると既存の取込を壊すため。
- 余分な diff を出さない。

## 入力ファイル

利用者が書き出せるのは3種類。文字コードは Shift-JIS か UTF-8。

### 仕訳1（1明細1行。借と貸が別の行）

```
行番号,仕訳日,仕訳No,アカウントコード,アカウント名,通貨コード,通貨名,貸借,科目コード,科目名,補助科目コード,補助科目名,金額,数量,外貨通貨コード,外貨通貨名,外貨金額,メモ,関連仕訳No,削除する場合「1」(半角)
```

### 仕訳3（1行に借と貸を並べる）

```
行番号,仕訳日,仕訳No,アカウントコード,アカウント名,通貨コード,通貨名,科目コード(借),科目名(借),補助科目コード(借),補助科目名(借),金額(借),数量(借),外貨金額(借),科目コード(貸),科目名(貸),補助科目コード(貸),補助科目名(貸),金額(貸),数量(貸),外貨金額(貸),外貨通貨コード,外貨通貨名,メモ,関連仕訳No,削除する場合「1」(半角)
```

### 科目（kamoku.csv）

```
科目コード,科目名,補助簿,補助科目コード,補助科目名,メモ,関連科目コード1,関連補助科目コード1,関連科目コード2,関連補助科目コード2,関連科目コード3,関連補助科目コード3,締日,支払サイト,支払日,通貨コード,通貨名,単価,償却月数,並び順(科目),並び順(補助科目),非表示(科目),非表示(補助科目)
```

補助科目の数だけ、同じ科目コードの行が繰り返される（例：101 現金 が 現金／edy／suica／nanaco の4行）。

### 分かっている値の形

- 日付は `2025/1/15`。既存の `normD`（`utils/csv.js`）で読める。
- 金額は `1,967,163` のようにカンマ入り。既存の `pAm` で読める。
- 仕訳No は13桁前後の数値。**利用者がExcelで開いて保存し直すと `2.02502E+13` のような指数表記に化け、全行が同じ値になる**（もらったサンプルがまさにそうだった）。仕訳No が使えなくても仕訳を組み立てられるように作る（後述）。
- 区切り文字：もらったサンプルはタブ区切りで貼られていた。実ファイルがカンマかタブかは未確認なので、**見出し行からどちらかを判定する**。
- 日本円以外の行（外貨）がありうる。
- 「削除する場合「1」」列が `1` の行は、向こうのアプリで削除予定の行。取り込まない。

## 変換の仕様

純粋関数として `utils/migrate/fukushiki.js`（新規）に置く。画面から切り離して、node で直接検証できるようにする。

### 1. 読み込み

- 文字コード：既存の `readCsvFile`（`utils/csv.js`）をそのまま使う（UTF-8で読み、化けたら Shift-JIS で読み直す）。
- 区切り：見出し行にタブがあればタブ、無ければカンマ。カンマ側は既存の `parseCL`（引用符対応）を使う。
- 形式判定：見出しに `貸借` 列があれば仕訳1、`科目コード(借)` があれば仕訳3、`補助簿` があれば科目。どれでもなければ「このファイルは読めません」と出す。
- 列は**見出しの名前で引く**。位置では引かない。全角括弧は半角にそろえてから比較する（既存の `toHalfParen` と同じ扱い）。

### 2. 明細行への分解

どちらの形式も、いったん「明細行」の列にそろえる：`{ rowNo, date, voucherNo, side: 'dr'|'cr', code, name, subCode, subName, amount, memo }`

- 仕訳1：1行＝1明細。`貸借` が `借` なら dr、`貸` なら cr。
- 仕訳3：1行＝最大2明細。借側と貸側で、それぞれ科目と金額があるものだけを出す。
- 次の行は捨てて、件数を数える：削除フラグが `1`、通貨名が日本円でも空でもない（外貨）、金額が0か空。

### 3. 仕訳へのまとめ方

**連続する明細を、借方合計と貸方合計が一致するまで束ねる。** 一致した時点で1件の仕訳として確定する。

- この方法なら仕訳No が化けていても組み立てられる。通常の仕訳（借1・貸1）も、複合仕訳（借1・貸2など）もそのまま扱える。
- 仕訳No が数字だけで書かれている場合（指数表記でない場合）に限り、**仕訳No が変わったところを区切りにも使う**。区切りで貸借が合っていなければ、その束はエラー。
- 束の途中で日付が変わったらエラー。
- 束が101明細以上になったらエラー（サーバーの上限が100、`backend/src/handlers/journals.js:8`）。
- 貸借の比較は1円未満の誤差を許す（サーバーは0.01、`journals.js:35`）。
- エラーになった束は取り込まずに、元の行番号つきで一覧に出す。1件のエラーで全体を止めない。
- 摘要：束の中で最初に空でないメモ。

補足：借1・貸1が偶然一致した直後に、本当は同じ仕訳の続きの行が来る場合もある。その場合は2件に分かれて記帳されるが、どちらも貸借が合っているので残高は正しい。これは許容する。

### 4. 科目の対応付け

対応付けの単位は**科目＋補助科目の組**（科目コード＋補助科目コード）。組ごとに、くろふくぼの科目を1つ割り当てる。

- 仕訳ファイルに出てくる組を一覧にする。科目ファイルもあれば、そちらの情報を足す（科目ファイルは補助科目1つにつき1行なので、1行＝1組になる）。
- 新しく作るときの科目名：
  - 補助科目が無い組（補助科目コードが空か0）は、科目名のまま（例：「保険一時金」）。
  - 補助科目がある組は `科目名（補助科目名）`（例：「普通預金（銀行 亀支店）」「給料（職場）」）。補助科目名だけにすると、「職場」「学校」のように何の科目か分からなくなるものがあるため。
  - 補助科目名が科目名と同じなら、科目名だけにする（「現金（現金）」にしない）。
  - 画面で名前を書き換えられるようにする。
- くろふくぼの既存科目と、**上の規則で作った名前が一致すれば自動でそこへ割り当てる**（既存の `resolveAccount`）。補助科目が無い「現金」や、補助科目名が科目名と同じ「現金／現金」は、既定の「現金」に当たる。
- 一致しなければ、既定の動作は「新しい科目を作る」。区分は科目コードの先頭の桁から推定する：1＝資産、2＝負債、3＝純資産、4＝収益、5＝費用。同じ科目コードの組はすべて同じ区分になる。**これは推定**（サンプルで確認できたのは1・4・5だけ）なので、画面で区分を変えられるようにする。先頭の桁が1〜5以外なら区分を空にして、選ばないと取込ボタンが押せないようにする。
- 新しく作る科目のコードは既存の `nextCode`（`utils/accountCode.js`）で振る。向こうの3桁コードは持ち込まない（既定科目の4桁と並び順が混ざるため）。同じ科目コードの組が並ぶよう、科目コード→補助科目コードの順に採番する。
- 科目ファイルで「非表示(科目)」か「非表示(補助科目)」が `1` の組は、`hidden: 1` で作る（9/23 にリリースした科目の非表示機能）。
- 利用者は、各組について「既存の科目に割り当てる」か「新しく作る（名前・区分を直せる）」を画面で選べる。複数の組を同じ科目に割り当ててもよい（補助科目をまとめたい人向け）。

### 5. 重複の除外

移行は途中で失敗して再実行されることがある。二重取込を防ぐため、**既存の仕訳と「日付が同じで、明細の（科目・貸借・金額）の組が全部同じ」ものは、既定で取込対象から外す**。画面でチェックを戻せるようにする。

## 画面

- 入口：設定画面の「インポート / 移行」欄（`components/Settings/SettingsPage.jsx:137`）に「他のアプリから移行」ボタンを足す。既存の JSON 取込はそのまま残す。
- モーダル（新規：`components/Settings/MigrateModal.jsx`）の流れ：
  1. ファイル選択。仕訳ファイル（仕訳1か仕訳3）は必須、科目ファイルは任意。2つ同時に選べるようにする。
  2. 読み取り結果：仕訳の件数、明細の件数、期間（最初の日付〜最後の日付）、除外した行の件数（削除フラグ／外貨／金額0）、エラーの束の件数と行番号。
  3. 科目の対応付け：上の4の一覧。
  4. 取込。進捗を「n / 全件」で出す。取込中はモーダルを閉じられないようにする。
- **ゲストでは使えない。** ボタンは無効にして「アカウント登録すると使えます」と出す。ゲストには科目5件の上限があり（`config/tiers.js` の `GUEST_LIMITS`）、移行は必ず超える。
- 書き込みには既存の `addAccount` / `addJournal`（`contexts/DataContext.jsx`）を使う。ローカル・暗号化・API のどの保存方式でも正しく振り分けてくれる。`/api/import` による一括投入は使わない（仕訳の貸借検証を通らないうえ、暗号化利用者の場合は平文をサーバーに書いてしまう）。
- 数千件になるとAPIモードでは時間がかかる。まず1件ずつ投入で作り、実測して遅すぎるようなら後で改善する。

## 検証

テストフレームワークは無い。

1. **変換関数の検証**：node スクリプト（`docs/design-gen/verify-migrate.mjs` など）で `utils/migrate/fukushiki.js` を直接呼ぶ。テスト用のCSVは**見出しを上の仕様どおりにして、中身は架空の値で作る**（利用者のデータは使わない）。最低限含めるもの：
   - 仕訳1・仕訳3の通常の仕訳（借1・貸1）
   - 複合仕訳（借1・貸2）を両形式で
   - 仕訳No が指数表記に化けたファイル
   - 貸借が合わない束（エラーに出ること）
   - 削除フラグ `1`、外貨、金額0の行（除外件数に数えられること）
   - Shift-JIS で保存したファイル、タブ区切りのファイル
   - 補助科目：同じ科目で補助科目が違う明細（例：普通預金／亀支店と普通預金／ゆうちょ）が別々の科目になること、補助科目が無い明細・補助科目名が科目名と同じ明細が既存科目に当たること
   - 科目ファイル：補助科目つきの行、「非表示(科目)」「非表示(補助科目)」が `1` の行
2. **画面の検証**：`cd frontend && npm run dev`。ローカルはCORSでAPIが全滅するので、localStorage のモードで確認する。取込後に BS の資産・負債の合計が元ファイルの残高と一致すること、同じファイルをもう一度取り込むと全件が重複として外れること。
3. `npm run build` が通ること。
