# 依頼

iOS アプリのデザイン案を作ってください。成果物は **HTML 1ファイル**（`prototype.html`）です。
このメッセージだけで作業できるように書いてあります。前提知識は不要です。

---

## 1. これは何のアプリか

**iOS 向けの「複式簿記による資産管理」アプリ。**

家計簿アプリではありません。テーマは**資産管理**で、中心にあるのは
「純資産がいくらで、どう推移しているか」。支出の記録はそのための手段にすぎません。

- 個人開発・日本語のみ・iPhone 向け（iPad は考えなくてよい）
- 既に稼働中の Web 版があり、その iOS 版
- **Web 版とデザインを揃える必要はない。** モバイル固有の設計にしたい
- 利用者は複式簿記に馴染みがある人〜これから学ぶ人まで。専門用語（借方・貸方）は
  入力画面では隠し、レポートでは正しく使う

### 中核となる考え方（デザインにも効く）

- **ストック（資産・負債）とフロー（収入・費用）は別物。** 純資産は「今日時点の積み上げ」、
  収支は「今月分」。この2つを同じ見た目で並べると誤解を生む
- **帳簿が現実と一致していることが最重要。** 数字が合わないアプリは意味がない。
  「実査（実残高との照合）」という機能があり、これは目立つべき
- 記録の速さが正確さに直結する。レシートの出ない現金払いを取りこぼすと帳簿がずれる

## 2. 技術的な制約（守ってください）

- **React Native + Expo（SDK 54）／ expo-router**
- **UIライブラリを使わない。** NativeBase / Tamagui / gluestack 等は入れない。
  React Native の素のコンポーネント（View / Text / Pressable / ScrollView / FlatList）と
  StyleSheet だけで組む
- アイコンは `@expo/vector-icons`（Ionicons）が使える。SF Symbols 風のものを選べる
- **ライト／ダークの両対応が必須。** 配色はトークン経由で切り替える
- 文字はすべて日本語。**金額は等幅で桁が揃うこと**
- アニメーションを足すなら `react-native-reanimated`（導入済み）

**ティールはブランド色として維持したい。それ以外は変えてよい。**

### いまある共通部品

`Screen` / `Card` / `Kpi` / `Button` / `Field` / `Input` / `ChipRow` / `Empty`

- `Card` = 背景 `bg1`、1px の枠線、角丸14px、パディング14、要素間 gap10。
  見出しは11px・字間広め・大文字化した小さいラベル
- `Button` = 角丸999のピル。primary はティール塗り、ghost は枠線のみ
- `ChipRow` = 横スクロールする選択チップ列。科目や種別の選択に多用している
- 画面はほぼ全部「Card を縦に積む」だけ。**情報の重みづけが無く、どれも同じ強さに見える**

### 具体的に良くない点（作り手の自己申告）

1. **純資産という主役が、他のカードと同じ扱いで埋もれている**
2. カードの枠線が多く、画面が箱だらけに見える
3. iOS のネイティブアプリらしい要素が無い（大タイトル、リストのグルーピング、
   スワイプ操作、ハプティクス、シート、セグメンテッドコントロール等）
4. グラフが素朴（View を並べただけの棒グラフ）
5. 「管理」画面が機能の羅列で、頻度も重要度も反映されていない
6. 空状態がただの文字で、次に何をすればいいか分からない

## 4. いまある画面

### タブ（下部・5枚）

| タブ | 内容 |
|---|---|
| **ホーム** | 純資産＋6か月推移／当月の収入・支出・収支／支出の推移／予算の消化／支出内訳／投資資産 |
| **入力** | 一行入力（「食費 1200 現金」と打つ）／レシート撮影／プリセット1タップ／通常フォーム（支出・収入・振替）／タグ |
| **仕訳帳** | 一覧とカレンダーの切替。日をタップでその日だけ表示。タップで編集、長押しで削除 |
| **レポート** | 貸借対照表／損益計算書／キャッシュフロー／クレジットカードの締めサイクル（4つを切替） |
| **設定** | 同期／Face IDロック／リマインダー／管理画面への導線／ショートカット／使い方 |

### タブ外の画面

- 記帳の編集
- 撮って記帳（レシート・カード利用控えの読み取り。読み取り結果の確認 → フォーム）
- アカウント接続（ログイン・E2E暗号化の解錠）
- 管理（勘定科目／口座／タグ／プリセット／自動仕訳ルール／定期取引／予算／タグ配分／
  CSV取込・書き出し／実査・評価替え／暗号化）
- ショートカット設定、使い方、動作診断

## 5. 作ってほしいもの

**たたき台としてのビジュアルプロトタイプ。**

### 形式

**1枚の HTML ファイル**。ブラウザで開けば見られること。

- 外部CDN・外部フォント・画像ファイルを使わない（**単体で開けること**）
- iPhone 15 Pro 相当の枠（393×852）を並べて、**複数画面を一覧できる**こと
- **ライト／ダークを切り替えるボタン**を付ける
- 中の数字は現実的なダミーで埋める（純資産 4,820,000円 など。ゼロや Lorem ipsum は不可）
- 実装コードではなく**見た目の提案**。ただし React Native で再現可能な表現に留めること
  （CSS Grid、`position: sticky`、`backdrop-filter` の多用、複雑な擬似要素などは避ける。
  Flexbox・角丸・影・グラデーション・SVG は RN でも再現できる）

### 対象画面（この5枚）

1. **ホーム** — 純資産が主役だと一目で分かること
2. **入力** — 最短で1件を記録できること
3. **仕訳帳** — 一覧。日付・摘要・金額・科目が並ぶ
4. **レポート（貸借対照表）** — 資産・負債・純資産の構造が読めること
5. **管理メニュー** — 11項目を、頻度と重要度が伝わる形に整理

### 方向性

- **iOS ネイティブらしさ**: 大タイトル（Large Title）、インセットのグループ化リスト、
  セグメンテッドコントロール、シート、控えめな区切り線、SF Pro 相当のタイポグラフィ
- **モダン**: 余白を効かせる、枠線に頼らず階層を作る、数字を主役にする、
  色数を絞る、意味のある場所にだけ色を使う
- **金融アプリとしての節度**: 装飾過多にしない。数字が読みやすいことが最優先

### 提案は2案

**方向性の違う2案**を作り、同じ HTML 内に並べて比較できるようにしてください。
1案だけだと選びようがありません。それぞれに「何を狙ったか」を1〜2文で添えてください。
