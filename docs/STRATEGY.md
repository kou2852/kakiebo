# 戦略 再立案（2026-06）— 「家族の純資産OS」

第三者評価をもとにした再ポジショニング。担当：**【C】=Claude(私)実行可能** / **【U】=ユーザー操作必須**（コンソール・公開・意思決定・APIキー・デプロイ許可）。
※下部「# 事業戦略書（初版）」の料金・ユニットエコノミクス・ローンチゲートは引き続き有効。本節は**ポジショニング/差別化/SEO/競合/ロードマップを上書き更新**する。

## 1. 結論
「複式簿記家計簿」は差別化にならない（Firefly III / Actual Budget / ezBookkeeping / dLedger / MoneyBalance / Dualy が既存）。
→ **「家族の純資産OS（Net-Worth OS）」** へ再定義。複式簿記は“裏方”に隠す。
> ワンライナー：家族の“純資産”が見える家計簿。NISA・iDeCo・ローンまで一つに。しかも運営者にも中身は見えない。

## 2. 差別化の核（模倣されにくい3点セット）
1. **家族の純資産の一元化**（現金/証券/NISA/iDeCo/クレカ負債/住宅ローン → 1画面の「家族BS」）
2. **ゼロ知識プライバシー（E2E）＝既実装の最大の武器**（競合未保有）
3. **摩擦ゼロ入力**（一行＋AI＋裏で自動複式 → BS自動）
→ 既存実装（純資産ヒーロー・一行入力・BS/PL/CF・E2E）が土台。作り直し不要、“言葉・SEO・機能重点”の付け替えが中心。

## 3. 市場の不満＝刺す訴求
セットアップ地獄→既定科目＋テンプレ／スマホ入力辛い→一行＋AI＋モバイル最適化／家族で使いにくい→世帯共有・家族BS／投資管理弱い→NISA/iDeCo/証券統合／プライバシー不安→E2E。

## 5. SEO戦略
- **キーワード（“複式簿記”依存をやめ“資産/純資産”へ）**：主軸=`純資産 管理 アプリ`/`資産 見える化 アプリ`/`家族 資産 管理`/`世帯 資産 把握`。投資系=`NISA iDeCo まとめて 管理`/`総資産 推移 アプリ`。プライバシー系=`家計簿 プライバシー`/`ゼロ知識 家計簿`。ロングテール=`家族 バランスシート 作り方`/`純資産 計算 方法`。`複式簿記 家計簿`は主軸にしない（補助語）。
- **コンテンツ**：既存ガイド9本を資産/純資産寄りに再フレーム＋新規（家族BSの作り方／NISA・iDeCo・証券・ローンを含めた純資産／資産が増える家計の見方／プライバシーの仕組み）。内部リンク＋CTA。
- **技術SEO**：meta/OGPを純資産・プライバシー基調へ。`FinancialProduct`/`FAQPage`構造化データ。sitemap更新・速度・モバイル。

## 6. コピー案（3方向）
- **A 純資産軸**：「家族の“純資産”が見える家計簿」
- **B プライバシー軸**：「運営者にも見えない、家族のお金の全体像」
- **C 摩擦ゼロ軸**：「一行で書くだけ。家族の資産が自動でわかる」
→ 推奨：**Aメイン＋Bサブ併記**。

## 7. 実行ロードマップ（フェーズ×担当×完了基準）
- **P0 土台確定**：【C】本書✓ ／【U】方向性決定（A＋BでGoか）
- **P1 メッセージ反映(コード)**：【C】LP/アプリのコピー・meta・OGP・JSON-LDを純資産＋プライバシーへ改稿 ／【U】レビュー→デプロイ許可
- **P2 SEO基盤＋コンテンツ**：【C】KW設計(WebSearch調査)・記事ドラフト・内部リンク/sitemap/構造化データ ／【U】Search Consoleインデックス・AdSense再審査・X/Zenn/note/Reddit発信・被リンク
- **P3 差別化機能**：【C】純資産集約の科目テンプレ(NISA/iDeCo/証券/ローン)＋家族BSビュー・AI仕分け・入力摩擦低減 ／【U】優先度決定・AIのAPI承認・デプロイ許可
- **P4 計測・改善**：【C】軽量計測・KPI・A/B ／【U】解析確認・継続発信

## 8. KPI
インデックス数／主要KW順位／オーガニック流入／ゲスト開始数／登録転換率／記事→アプリCTR。

## ローンチゲート（公開可否の判断基準）

「いつ・何があれば世に出していいか」を3ゲートで定義する。前ゲートを満たさないと次に進めない。
**課金（Stripe）はゲート1に入れない** — 無料βで継続率と「どの機能に金を払うか」を観測してから料金設計を実データで検証する。

### 🚪 ゲート1: 無料β公開ライン（最優先）
| 項目 | 理由 |
|---|---|
| セキュリティ修正の本番再デプロイ | テナント分離・入力検証・CORS。未反映での公開は事故 |
| prodステージのデプロイ | devでは公開しない |
| S3+CloudFront ホスティング | フロント/LP配信基盤 |
| 独自ドメイン + SSL | 信頼性・SEO |
| CloudWatchアラート（最低限） | 公開後に落ちても気づける |
| kakeibo.html → クラウド版 移行導線 | 既存ユーザーが最初の有料候補。localStorageデータをインポート可能に |

### 🚪 ゲート2: 課金開始
無料βで継続ユーザーが見えてから（目安: WAU 30人 / 4週継続率40%超）。
- Stripe Checkout + Webhook → DynamoDBにプラン保存、Free枠（月仕訳数）制限
- **特商法表記・返金ポリシーは課金開始時に必須**

### 🚪 ゲート3: 本格集客（有料広告）
有料ユーザー50人超 & LTV>CACの目安が立ってから。それまでは無料チャネル（SEO/X/Zenn）のみ。

## 既存ユーザーの移行導線
