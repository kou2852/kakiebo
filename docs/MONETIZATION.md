# 収益化・広告方針

作成日：2026-09-05

## 決定事項

- **アプリ本体は無料。**ダウンロードに課金しない
- **課金対象は広告の非表示だけ。**機能差は作らない
- 商品タイプは **App内課金の非消費型（Non-Consumable）**。買い切りで永続
- 自動更新サブスクは採用しない。Guideline 3.1.2 の要求（購入画面に価格・期間・
  タイトルの明示、利用規約とプライバシーポリシーへのリンク）が重く、家計簿で
  「広告を消す」に継続課金の説得力が弱いため

### 機能差を作らない理由

家計簿で機能を削って売ると、無料側が「使えないアプリ」に見えて評価を下げる。
広告だけを外す形なら、無料側の体験を損なわない。
`AD_TIERS` の `pro` / `family` は広告の可否だけを定義しており、機能制限は
どこにも実装していない。この状態を維持する。

## 広告の切り替えについての禁止事項

**⚠ 広告の挙動を切り替えるフラグを作らないこと。**

別アプリ SUKIMA QUEST で、広告の挙動をビルド時フラグで切り替え、同一バージョン
1.0.0 へ挙動の異なる3つのバイナリを上げ、広告を無効化したビルドからストアの
スクリーンショットを撮ったところ、**2026-08-26 に Guideline 5.6
（Developer Code of Conduct）で却下された**。指摘は「審査中に意図的に隠されたと
見える機能がある」。開発者アカウント自体に関わる重い条項で、善意でも審査を
欺いたと読まれる。

したがって:

- テスト広告は `__DEV__` のときだけ。ストア配布ビルドは常に本番ユニットを使い、
  ビルド時にも実行時にも切り替える手段を持たない
- ストア配布のプロファイルは1つだけ。TestFlight 配布も審査提出も同じビルド
- スクリーンショットは出荷ビルドで撮る。**広告が写り込むこと自体は問題ない**
- 自分の広告を踏まない対策は、ビルドを分けることではなく
  `mobile/src/ads.js` の `TEST_DEVICES` に端末を登録すること
- **課金の実装でも同じ。**「購入済みかどうか」を開発用フラグで切り替えない。
  審査担当はサンドボックスで実際に購入して確認する

## 実装計画

### ライブラリ

`expo-in-app-purchases` は廃止済み。**`expo-iap`（Expo Module）** を使う。
買い切り1商品に RevenueCat のような外部サービスを挟む必要がなく、
「家計データを外部に出さない」という訴求とも整合する。

### 商品

| | |
|---|---|
| 商品ID | `com.kurofukubo.app.noads` |
| 参照名 | 広告非表示 |
| タイプ | 非消費型 |
| 価格 | **未定** |

### 追加するファイル

```
mobile/src/store/PurchaseProvider.jsx   権利の取得・購入・復元
mobile/src/purchases.js                 商品IDと expo-iap の薄い包み
mobile/app/settings/purchase.jsx        購入画面
```

### 変更するファイル

```
mobile/src/components/TabBar.jsx    <AnchoredAd /> に tier を渡す
mobile/src/components/Ad.jsx        AD_TIERS を実際に効かせる
mobile/src/ads.js                   購入済みなら SDK の初期化ごと止める
mobile/app/(tabs)/settings.jsx      購入と復元への導線
```

バナーを隠すだけでは広告リクエストが飛び続ける。**SDK の初期化自体を止める。**

### 権利の保存場所

**SecureStore に保存する。** 理由:

- オフラインでも即座に効く必要がある（本アプリはオフラインファースト）
- **暗号化ブロブの中に入れない。**解錠前に読めないと、パスフレーズ入力中に
  広告が出てしまう
- 買い切りは Apple ID に紐づくため、端末間は「購入を復元」で成立する。
  サーバー側の権利管理は不要

### 「購入を復元」は必須

Guideline 3.1.1 の要求。見つけにくい位置に置くと指摘される。
MACHINAKA LOG では、実装済みの機能が「小さな灰色のラベルで見逃しやすい」と
Apple に指摘された前例がある。設定画面の分かりやすい位置に置く。

### サーバー側は実装しない（2026-09-05 確定）

**Web 版は課金の対象外。**Web には広告を出せていないため、消すものが無い。
したがって端末をまたぐ権利管理も要らず、サーバー側の実装は不要。

買い切りは Apple ID に紐づくので、機種変更や再インストールは
「購入を復元」で足りる。

将来 Web に広告を出し、そちらも対象にする場合に限って次が必要になる:

- DynamoDB に `SK: 'ENTITLEMENT'` を追加（`PK: USER#<userId>`）
- レシート検証を通して書き込む
- **ゲストは同期できない**（アカウントが無いため）

## 着手前に必要なもの

- [ ] **有料App契約（Paid Applications Agreement）の締結**
      名前に「有料App」と付くが、**App内課金だけの場合も必須**。
      銀行口座と税務情報の登録も要る。承認まで日数がかかることがある。
      App Store Connect →「契約/税金/口座情報」で状態を確認する
- [ ] 価格の決定
- [x] ~~Web 版も対象にするかの決定~~ 2026-09-05 に対象外で確定

## テスト

Windows には Xcode の StoreKit ローカルテストが無い。
**TestFlight + サンドボックス用 Apple ID** で実機確認する。

## リリース方針

初回リリース（0.1.x）は**広告ありで出す**。課金は 0.2.0 で追加する。
有料App契約の承認待ちで初回リリースを止めない。
