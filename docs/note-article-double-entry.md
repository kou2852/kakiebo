# 複式簿記の家計簿を作るときに、捨てた3つのもの

家計簿を複式簿記でつけられるWebアプリを作っています。「黒福簿（kurofukubo）」といいます。

複式簿記そのものの説明は、すでにいろいろな人が書いています。私が書けるのは、**作るときに何を選んで、何を捨てたか**のほうです。この記事はそちらを書きます。

なお複式簿記と単式簿記の違い自体は、別のページにまとめてあります。用語から知りたい方はそちらへ。

→ [複式簿記の家計簿｜単式との違いは資産・負債・純資産まで見える](https://kurofukubo.com/guide-double-entry.html)

## そもそも、なぜ複式にしたのか

複式にした理由は、**支出の詳細な管理と、お金の「目的別の管理」を、同時に成立させたかったから**です。

家計簿でこの2つは、ふつう別々の話として扱われます。

ひとつめは「何に使ったか」。食費がいくら、光熱費がいくら、という費目の話です。これは単式の家計簿でもできます。

ふたつめは「このお金は何のためのお金か」。口座に80万円あるとして、そのうち生活費が30万、旅行の積立が15万、税金の支払い用が20万、残りが自由に使える分、という見方です。いわゆる袋分けや目的別貯金にあたります。

問題は、**ふたつめをやろうとすると口座を物理的に分けるしかない**ことです。目的の数だけ口座を開き、給料日に振り分けて回る。管理する対象が増えるほど面倒になり、そのうち崩れます。

複式簿記にすると、この2つが**同じ1回の入力で同時に埋まります**。

複式では取引を必ず両側で書きます。片側は費目（何に使ったか）、もう片側は口座（どこから出たか）です。**費目の側で「ひとつめ」が、口座の側で「ふたつめ」が処理できる。** 単式は費目の側しか持っていないので、ふたつめをやる場所がありません。

そこで、口座の残高にタグで配分をかけられるようにしました。

| タグ | 配分 |
|---|---|
| 生活費 | 300,000 |
| 旅行 | 150,000 |
| 税金 | 200,000 |
| **未配分** | **150,000** |
| 口座残高 | 800,000 |

口座はひとつのままです。**分けているのは金額の意味だけ**で、実際のお金は動かしていません。残高から配分の合計を引いた「未配分」が、本当に自由に使える額になります。配分を超えて使えばマイナスで出ます。

配分は手で置くこともできますし、記帳のときにタグを付ければ、その分は仕訳から自動で拾われます。

## 捨てたもの① 銀行連携

いちばん大きい決断でした。**口座やカードを連携して明細を自動で取り込む機能を、作らないことにしました。**

自動連携は便利です。これは間違いない。手入力の面倒くささが家計簿を続けられない最大の理由なので、それを消せるなら消したほうがいい。

それでもやらなかったのは、連携するとは**金融機関のIDやトークンを預かるということ**だからです。預かる以上、預かった側には守る責任が生まれます。個人で作っているものが、その責任を引き受けるべきかを考えて、引き受けないことにしました。

代わりにこうしました。

- 手で入力する（一行で書けるようにした。後述）
- CSVを取り込む（他の家計簿サービスのCSVも、形式を自動判定して読みます）

自動化を求める人にとって、これは明確な弱点です。そこは正直に書いておきます。一方で「口座は外部サービスに繋ぎたくない」という人にとっては、そもそも繋げないことが利点になります。

同じ理由で、保存したデータも端末側で暗号化できるようにしました。設定でオンにすると、鍵はサーバーに送られません。つまり**運営している私が中身を読めなくなります**。オフのままなら読めてしまう状態なので、そこも隠さず書いています。

→ [家計簿データは誰が見られる？E2E暗号化なら運営者も読めない](https://kurofukubo.com/guide-privacy.html)

## 捨てたもの② 登録

**メールアドレスもパスワードも入れずに使えるようにしました。**

最初にログイン画面は出ますが、そこに「登録なしで試す」があります。押すとそのまま家計簿が始まります。

これを入れたのは、複式簿記の家計簿が**「説明を読んでも、さわってみないと分からない」**タイプの道具だからです。借方・貸方の説明をどれだけ丁寧に書いても、実際に1件記帳してBSが動くのを見るまでは腹に落ちない。その1件までの距離を、できるだけ短くしたかった。

登録を必須にすると、この距離のあいだに「メールアドレスを渡すかどうか」という判断が挟まります。まだ良いかどうか分かっていない道具のために、それを判断させるのは順番が逆だと思いました。

## 捨てたもの③ 簿記の言葉

複式簿記の家計簿アプリが難しくなる原因の多くは、**画面が簿記の言葉のままであること**です。借方、貸方、勘定科目、仕訳。これらは正確な言葉ですが、日々の入力画面に出てくる必要はありません。

なので入力欄はこうしました。

```
食費 1200 現金 / コンビニ
```

これを打つと「借方：食費／貸方：現金 1200円」に変換されて記帳されます。**書いている側は複式簿記を意識していないのに、出てくる帳簿は複式簿記になっている**、という状態を目指しました。

ここは今も一番悩んでいる部分です。言葉を隠すと入り口は下がりますが、**隠しすぎると「なぜBSが動いたか」が分からなくなる**。いまは詳細モードで仕訳の形も見られるようにして、両方残しています。

## 捨てなかったもの：2つの軸

削らなかったのは、記事の最初に書いた2つの軸そのものです。

**ひとつは、タグによる残高の配分。** これが複式にした直接の理由なので、当然ここは残ります。ダッシュボードでも、口座ごとの配分と未配分が見えるようにしています。

**もうひとつは、貸借対照表（BS）と損益計算書（PL）、それに純資産の推移です。** 費目の側を積み上げていくと自然にこうなります。

この2つが揃うと、家計の見方がひとつ増えます。「今月いくら使ったか」だけでなく、**「家全体のお金がいくら増えたか」**と**「そのうち自由に使えるのはいくらか」**が同時に出る。

たとえば、支出が先月より5万円少ないのに預金が減っている月があります。先月使ったカード代が今月引き落とされた、というだけの話ですが、単式の家計簿はこれを「支出が減ってよくできました」としか言いません。BSとPLを並べると、なぜそうなったかが一目で分かります。

→ [家計のBS・PLの作り方｜黒字7万円で純資産が8万円増える理由](https://kurofukubo.com/guide-bs-pl.html)

## まとめ

作るときに置いた優先順位は、こうでした。

| 捨てたもの | 代わりに得たもの |
|---|---|
| 銀行連携 | 認証情報を預からない。端末側で暗号化できる |
| 登録 | 最初の1件までの距離が短い |
| 簿記の言葉 | 一行で書ける入力欄 |

そのうえで残したのが、費目による支出の管理と、タグによる残高の配分。この2つを同時に回すために複式にした、というのが全体です。

便利さを削っている自覚はあります。自動で全部入ってほしい人には向きません。ただ、**口座を分けずに目的別の管理をやりたい人**には、複式はかなり素直な手段だと思っています。

登録なしで試せます。合わなければ閉じるだけです。
