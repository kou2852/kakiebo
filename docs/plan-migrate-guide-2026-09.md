# 移行ガイド記事を作り、アプリの説明ページにする（2026-09-25）

「他のアプリから移行」を触ってもらったところ、**全体的に説明がないと操作できない**と指摘を受けた。LP のガイド記事として移行の記事を1本作り、それをアプリ内の説明ページにする。

前提になっている仕様：`docs/plan-migrate-generic-2026-09.md`（移行ツールの仕様。末尾に画面の作り直しと仕訳明細の画面の決定）。

## 結論

- **LP に記事を1本新設する**（案：`/guide-migrate.html`「他の家計簿アプリからデータを移行する手順」）。アプリ内に別のヘルプは作らない（説明を2か所で持つと、画面を変えたときにどちらかが古くなる）。
- **アプリの移行画面から、記事の該当の節へリンクする**（ファイル選択・列のマッピング・科目のマッピング・仕訳明細の4か所）。**新しいタブで開く**（同じタブで開くと、途中まで作ったマッピングと直した仕訳が消える）。
- **既存の2記事の移行の記述を直す。** いまは「CSV取込」で移行する案内になっていて、しかも実際の Zaim のファイルは CSV取込では0件になる（誤案内）。

記事にする理由：検索から来る「乗り換え」の人にも同じ説明が届く、画像と文を1か所で直せる、GA4 でどの画面から説明を開いたかを数えられる。

## 記事の構成（節ごとにアンカーを付け、アプリからそこへ飛ばす）

| アンカー | 節 | 書くこと |
|---|---|---|
| `#overview` | できること・できないこと | 科目と仕訳をまとめて取り込める／ファイルは端末の中だけで読む（送信しない）／日本円以外・予算・定期取引は移行しない／アカウント登録が必要（ゲスト不可）／パソコン推奨（スマホは表が横にスクロールする） |
| `#flow` | 全体の流れ | 「ファイルを選ぶ → マッピング（列と科目）→ 仕訳明細 → 取込」を画面の縮小図つきで。どこで何を決めるかを1画面1行で |
| `#export` | アプリ別の書き出し方 | 複式家計簿（Android）・マネーフォワード ME・Zaim の書き出し手順と、**有料機能かどうか**（下の「分かっている事実」）。その他のアプリは「CSV か JSON で書き出せれば取り込める」 |
| `#file` | ファイルを選ぶ | 複式家計簿は kamoku.csv も選べる（任意）／「1行目は見出し」を外すファイル（弥生会計の仕訳など）／JSON は取引の配列を選ぶ |
| `#columns` | 列のマッピング | 左＝元の列、右＝くろふくぼの項目の見方。**自動で入るアプリ**と**自分で選ぶアプリ**。「元データの形」3種の見分け方（1行に1取引＝単式／1行に借方か貸方の一方／1行に借方と貸方）。収支・貸借がどの列で決まるか。取り込まない行 |
| `#columns-examples` | 列の選び方の例 | 自作の Excel 表（入金額・出金額が別の列・口座の列なし）と、弥生会計の仕訳日記帳（見出しなし）の2例を、実際の選び方の表で |
| `#accounts` | 科目のマッピング | 新しく作る／既存の科目にまとめる、補助科目は別の科目になる、区分（資産・負債…）の推定と直し方 |
| `#review` | 仕訳明細 | 赤い仕訳の直し方（「＋」で差額の行が入る → 科目を選ぶ）、並び順（科目の順）、取込済みと同じ仕訳 |
| `#trouble` | うまくいかないとき | 借方と貸方が合わない／日付が読めない／文字化け（Shift-JIS・UTF-8 は自動で判定）／Excel で保存し直して番号が「2.02502E+13」に化けた／二重に取り込みそう（重複は外れる） |
| `#after` | 取り込んだあとに | 残高照合（実査）で通帳と合わせる → タグで口座残高を目的別に配分 → 純資産・BS が見える（訴求の主役に沿う。一行入力には触れない） |
| （FAQ） | よくある質問 | 3〜5問。FAQPage の構造化データにも入れる |

- 見出し・本文は既存のガイド（`guide-csv.html`）の型に合わせる：`BlogPosting`・`BreadcrumbList`・`FAQPage` の JSON-LD、パンくず、途中と末尾の CTA（`utm_source=guide&utm_medium=article&utm_content=guide-migrate` / `guide-migrate-mid`）、著者・更新日。HowTo の構造化データは使わない（Google がリッチリザルトを止めている）。
- 訴求の主役は「純資産 × タグの目的別配分」。書き終えたら「一行入力」「クイック入力」の出現を数え、主役の位置に無いことを確かめる。

## 分かっている事実（執筆時に公式の出典をもう一度確かめ、記事に出典を書く）

- **マネーフォワード ME の CSV ダウンロードはプレミアム会員のみ。** アプリは「入出金」→ ダウンロードのアイコン（1年分）、Web は「収入・支出詳細」から1か月ずつ。
  出典：[入出金履歴はダウンロードできますか](https://support.me.moneyforward.com/hc/ja/articles/900004382483)・[1年間の入出金履歴はダウンロードできますか](https://support.me.moneyforward.com/hc/ja/articles/9778603118873)
- **Zaim の CSV ダウンロードはプレミアムの機能**（無料のお試しあり）。Web 版の「設定」→「ファイル入出力」。
  出典：[CSVのダウンロード（Zaim ご利用ガイド）](https://content.zaim.net/manuals/show/37)・[ファイル入出力](https://content.zaim.net/money)
- **複式家計簿（Android）は「その他設定・各種操作」→「データエクスポート」で仕訳と科目を書き出す**（2.1.16、2024-02-26 から）。
  出典：[Google Play の掲載](https://play.google.com/store/apps/details?id=com.gomao.kakeibo)（更新履歴）。画面の名前は問い合わせでもらった列構成と合っているが、**メニューの正確な名前は執筆時に Google Play の更新履歴で確かめる**。
- 既存の記事（`guide-moneyforward.html`）は、マネーフォワードの書き出しが有料であることに触れていない。新しい記事では最初に書く（書き出せないと始まらないため）。

## 計測

- アプリ → 記事のリンク：`https://kurofukubo.com/guide-migrate.html?utm_source=app&utm_medium=referral&utm_campaign=migrate_help&utm_content=<場所>#<節>`。`<場所>` は `file` / `columns` / `accounts` / `review`。
  - LP には GA4 があるので、**どの画面で説明を開いたか**がそのまま数えられる（アプリ側の計測は足さない）。
  - `utm_medium` は GA4 のチャネルに乗る語（`referral`）にする。既存のアプリ → LP のリンク（`AuthPage.jsx` の `utm_medium=auth`）は独自の語で Unassigned に落ちるので、今回は合わせない。
- 記事 → アプリの CTA は既存のガイドと同じ `utm_source=guide&utm_medium=article`。
- 公開後に見る数字：`utm_campaign=migrate_help` の `utm_content` 別のページビュー（どの画面で詰まるか）、記事への検索流入。

## 決めてほしいこと

   - (b) ゲストでもマッピングと仕訳明細までは見られるようにし、取込だけ登録を求める
3. **CSV取込の Zaim の読み取り**：直して記事の記述を正しくするか、記事から Zaim の記述を外すか。
4. **LP の未コミットの変更**：`guides.html`・`sitemap.xml` の別の作業の変更を、今回一緒に出してよいか（だめなら、その変更を外した版を作って出す）。
5. **アプリのリンクを置く場所**：上の4か所に加えて、設定画面の移行の説明文と、CSV取込の案内の行にも置くか。
