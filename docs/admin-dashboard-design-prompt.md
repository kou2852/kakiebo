# Claude Design 用プロンプト — 管理ダッシュボードの見た目を整える

> **2026-08-02 対応済み。** 下記の指摘はすべて `scripts/admin/server.mjs` へ反映済みで、
> 未解決の課題ではない。プロトタイプ（`admin-dashboard-prototype.html`）も刷新前の状態のまま。
> 次に見た目を直すときは、現行の `server.mjs` から作り直すこと。


`docs/admin-dashboard-prototype.html` を添付して、以下をそのまま渡す。

---

## 依頼

添付した1枚のHTMLは、個人開発の家計簿SaaS「kurofukubo（黒福簿）」の**運営者だけが見る管理ダッシュボード**です。
localhost でだけ動き、見るのは**開発者1人**。数字を毎日ざっと眺めて「今どこで人を失っているか」を判断するために使います。

機能は足りているのですが、**情報が全部同じ見た目で並んでいて読み取れません**。見た目とレイアウトだけを整えてください。

## 絶対に守ってほしい制約

1. **1枚の自己完結HTMLで返してください。** 外部CDN・Webフォント・画像・ライブラリの読み込みは一切不可（オフラインのlocalhostで開きます）。CSSは`<style>`に、JSは`<script>`にインラインで。
2. **JavaScriptのロジックとデータ構造は変えないでください。** このHTMLは実際にはNode製サーバー（`scripts/admin/server.mjs`）内のテンプレート文字列で、`render()` / `renderFeedback()` / `funnelSection()` が組み立てています。**関数名・データのプロパティ名・`fetch`の呼び先はそのまま**にしてください。
3. **HTMLの中でバッククォート（`）と `${` を使わないでください。** テンプレート文字列の中に戻すため、使われると構文が壊れます。文字列連結は今と同じ `'...' + x + '...'` の形で。
4. 冒頭の `PROTO_STATS` / `PROTO_FEEDBACK` と `window.fetch` の差し替えブロックは**プロトタイプ用のダミー**です。**そのまま残して**ください（こちらで外します）。
5. **表示している数字・項目を減らさないでください。** どれも見る目的があります。並べ方・まとめ方・強弱は自由に変えて構いません。
6. **解釈やアドバイスの文言を足さないでください。**「改善しましょう」「良好です」等は不要です。数字だけを見せる方針です。

## 今の問題（優先度順）

### 1. 最も大きい数字が「ボット」で、目が最初にそこへ行く
上部のKPIカードは7枚が同じ大きさで並び、`626`（ボット）が画面で一番大きい数字になっています。
実際に重要なのは **登録ユーザー数・実人数・ファネル**で、ボットは「ノイズがこれだけある」という補足でしかありません。
**重要度に応じた強弱**をつけてください。ボット・self は小さく端に寄せて構いません。

### 2. カードが7枚で中途半端に折り返す
`auto-fit, minmax(150px, 1fr)` のため、最後の1枚だけが次の行に落ちて不格好です。

### 3. 「アクティベーション 0.1」が何のことか分からない
ラベルだけあって文脈がありません。分子・分母が見えるようにしてください（記帳イベント÷ゲスト開始）。

### 4. 自前イベントの一覧が生の識別子のまま
`tour_step_account-add` `tour_skip_welcome` のような**内部の名前がそのまま12行**並んでいます。
日本語の説明を添える、種類ごと（ツアー / 獲得 / 継続 / アンケート）にまとめる、などして読めるようにしてください。
対応は以下です。

| 識別子 | 意味 |
|---|---|
| `app_open` | 起動（回数） |
| `app_first` | 初回起動＝新規訪問者（人数） |
| `auth_view` | ログイン画面を見た（人数） |
| `guest_start` | ゲスト開始（回数） |
| `guest_first` | ゲスト開始（人数） |
| `guest_return` | 既存ゲストの再訪（回数） |
| `journal_added` | ゲストの記帳（回数） |
| `first_journal` | 初回記帳（人数） |
| `registered` | 登録（人数） |
| `retain_d1` / `_d7` / `_d30` | 1/7/30日後に再訪（人数） |
| `account_deleted` | 退会 |
| `feedback_shown` / `feedback_shown_monthly` / `feedback_sent` | アンケート表示・送信 |
| `tour_step_<名前>` | ツアーの各ステップ到達 |
| `tour_skip_<名前>` | そのステップで離脱 |
| `tour_done` / `tour_done_acted` / `tour_sample` | ツアー完走 / 完走かつ記帳 / サンプル閲覧 |

### 5. 「日別の内訳」が1行の長い文字列で完全に読めない
`tour_step_account-add=2 guest_start=12 tour_step_welcome=12 ...` が横に伸びて切れています。**最優先で直したい箇所**です。

### 6. 日別オープンが13行の表で、推移が見えない
数字は必要ですが、**傾向が一目で分かる形**（折れ線・棒など。ただし外部ライブラリ不可なのでCSSかインラインSVGで）にしてください。
7/22 に bot が 376 と突出しており、これがスケールを壊しています。人間とボットは分けて見せた方がよいかもしれません。

### 7. ボットUA一覧が長すぎる
URLエンコードされた長大な文字列が7行。参考情報なので、**折りたたむ／末尾に小さく置く**程度で十分です。

### 8. 最下部に自分のIPが大量に並んで壁になっている
「集計時刻 / 対象ログ / 自分IP」の行が、IPv6アドレス十数個で数行にわたっています。件数だけ見せて詳細は畳んでください。

### 9. ファネルと継続が下に埋もれている
**この2つが一番見たいもの**です。上部に持ってくる、または視覚的に主役にしてください。
「ゲスト開始した人のうち記帳まで到達: 12.2%」のような**率**が読み取りやすいと嬉しいです。

### 10. 「ご意見」タブ（ヘッダーのタブで切替）
ユーザーから届いた自由記述が並びます。今は素っ気ない区切り線だけです。読み物として読みやすくしてください。
※プロトタイプのご意見4件は**体裁確認用のダミー**で、実際の投稿ではありません。

## デザインの方向性

- アプリ本体と同じ配色を使ってください。CSS変数が既に定義済みです（`--ac` #0d9488 がブランド色）。**この配色は変えないでください。**
- 落ち着いた実用重視のトーン。派手さは不要です。装飾より**情報の階層**を優先してください。
- 主にPC（1280px前後）で見ますが、スマホ（390px）でも横スクロールが出ないようにしてください。
- ダークモードは不要です。

## 補足（データについて）

- 数字は本物です（直近14日）。ただし**ファネルと継続の数値だけは仮**です。計測を入れたばかりでログにまだ乗っていないため、傾向が分かる値を入れてあります。
- 「人数」はブラウザ単位で1回だけ送るイベントの数、「回数」は毎回送るイベントの数です。両者が混在するので、**どちらなのか分かる表記**にしてもらえると助かります。
